# Contributing to TrustIn

TrustIn is currently **In Development**.

## Development principles

1. Keep the architecture chain-agnostic.
2. Keep PII and large files off-chain; anchor commitments/hashes only.
3. Keep ownership separate from authorization.
4. Treat asset integrity as an authorization condition.
5. Never claim a simulation as a live cryptographic implementation.
6. Add tests for state transitions, access-control invariants and recovery paths.

## Suggested workflow

Create a branch, make a focused change, add/update tests or documentation, and open a pull request explaining what is implemented and what remains in development.
